## 页面状态传递

### 设备信息传递

```
首页 → AI分析页 → 理疗管理页
  │
  └── selectedDevice ─────────→ deviceStore
```

### 理疗数据传递

```
AI分析页 → 理疗管理页
  │
  ├── aiAnalysis (分析结果)
  ├── methods (选择的手法)
  └── deviceInfo (设备信息)
```

### 状态存储

| 数据 | 存储位置 | 说明 |
|------|----------|------|
| 用户信息 | userStore | 全局状态 |
| 登录状态 | userStore + localStorage | 持久化 |
| 设备列表 | deviceStore | 全局状态 |
| 当前设备 | deviceStore | 全局状态 |
| 理疗参数 | therapyStore | 全局状态 |
| 手法选择 | therapyStore | 全局状态 |

## 路由守卫逻辑

```javascript
// 路由守卫
router.beforeEach((to, from, next) => {
  const userStore = useUserStore()
  
  // 需要登录的页面
  if (to.meta.requiresAuth) {
    if (!userStore.isLoggedIn) {
      next('/login')
      return
    }
  }
  
  // 已登录用户访问登录页
  if (to.path === '/login' && userStore.isLoggedIn) {
    next('/home')
    return
  }
  
  next()
})
```

## 状态管理

使用Pinia进行全局状态管理:
- `userStore`: 用户信息、登录状态
- `deviceStore`: 设备列表、连接状态
- `therapyStore`: 理疗参数、手法选择、计时器

## 未来拓展时的逻辑参考

当添加新页面时，需要：

1. **路由配置**: 在路由数组中添加新路由
2. **路由守卫**: 在路由守卫中添加权限控制
3. **状态存储**: 在对应的Store中管理状态
4. **导航入口**: 在相关页面添加入口按钮
5. **返回逻辑**: 确保有返回上级页面的入口
