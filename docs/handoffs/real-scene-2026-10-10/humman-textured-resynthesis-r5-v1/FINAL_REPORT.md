# R5 首批摄影纹理再合成：完成结果

2026-10-10。实际完成 **12个真人源身份、48个扫描动作帧、1152张 RGB-D**。9个身份/864图 TRAIN，3个身份/288图 VAL。原生 MHR 的旧4000图和R3/R4模型保持原样；本轮没有启动训练，没有读取封存 TEST 图像或目标。

## 做成了什么

下载、阅读了 SURREAL、BEDLAM、BEDLAM2.0、SynBody、HuMMan 的方法和相关图；将“摄影纹理、衣物几何、固定人体再移动相机、分身份划分”的做法落实到实际生成代码。

从官方 HuMMan-Recon 的不可变 ZIP revision 选择性提取144个 OBJ/MTL/PNG 文件，总原始439,794,603 bytes；所选条目压缩合计132,785,372 bytes，避免整包约23.7GB下载。服务器完成直连下载，显式关闭 requests 代理继承，使用同一 revision 的 HF 镜像。服务器与本地144个文件 SHA256 完全一致。

每个固定扫描体拍12个虚拟相机视角、两种光照；实际保留源摄影纹理、衣物褶皱、头发和鞋，搭建实体摄影棚地面与 HDRI 灯光。保存 RGB、人体 clean/noisy Z、场景 clean Z、mask/bbox、原图相机、完整表面几何和源→场景变换。

## 判断与边界

这条资产路线可行：能把现成的真人摄影纹理 Mesh 放入可控仿真相机中生成 RGB-D，比继续增加光滑彩色 MHR 的重复视角更有外观信息。

但这只是首批管线与外观验证，尚不能判断模型变准。只有12个源身份，一个摄影棚、两个仰角；部分动作帧很近似，尤其 p000599 四帧几乎都叉腰。源帧数量、视角数量不能等同独立动作或独立真人数量。也不覆盖最终俯卧裸背治疗场景。

最重要的标签区别：**本批没有原生 MHR 参数或对应顶点真值**。扫描衣物外表面不能当裸身体表；虚拟相机外参不能当 MHR pred_cam_t；现有参数监督 loader 不能直接混入新样本填零参数。见 [训练接入说明](TRAINING_INTEGRATION.md)。

下一步应先做几何监督的数据接入，并增加源动作覆盖、独立距离/焦距分布，再以相同模型、预算和seed比较“旧数据”与“旧数据＋新数据”。本轮不因外观变逼真就宣布可以发论文或工程定位达标。

代码、来源、计划、全量清单、QA、直连下载及备份回执均在本目录或其代码链接；完整数据保存在服务器和私有备份，原始数据、权重和论文全文不入Git。

## 运行与保存

正确版本的批量渲染在本地 CPU 上运行两个互不重叠的 Blender 进程；较长进程用时1473.3秒，约24.6分钟。该时间不包含源下载、打包和上传，不代表 GPU 速度。

完整数据已在 AutoDL 解压，服务器重新计算1152个样本 SHA 全部一致，并核对48个共享几何、1152张原始渲染 PNG 和864/288身份划分。见 [服务器文件核查](SERVER_DATASET_QA.json) 与 [传输回执](SERVER_GENERATED_RECEIPT.json)。源数据与生成数据的两个压缩包均已在172.18.6.218私有备份校验。本轮未开启付费 GPU，服务器保持运行。

下一批可对同一24图测量 CPU/GPU 总耗时再选设备。当前生成脚本显式使用 CPU；切换实例模式并不会自动启用 GPU，需要配置 Blender Cycles 设备。下载、CPU深度打包和压缩仍需分别计时。
