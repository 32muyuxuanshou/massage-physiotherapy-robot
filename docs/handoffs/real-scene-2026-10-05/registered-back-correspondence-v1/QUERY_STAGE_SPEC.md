# 连续方法推进：Canonical query → 可见表面匹配 V1

主对应场机制实验已完成并看到结果。后续沿同一角色继续开发，080–099从本阶段起明确是**已消费机制验证来源**，不再声称新留出泛化。

改动只在任务输出：不用预测整条参考线或固定26个类别。输入任意canonical XYZ query，网络输出它与当前可见表面候选的匹配分数；查询可以由后续工程atlas/规则生成。学习只用000–059来源的对应标签，不使用医生标签、DMD37或测试GT进行训练。

两网络：Q_GLOBAL（局部XYZ/法向+全局max）；Q_PRIOR_LOCAL（增加固定模板近邻条件+12近邻边编码）。query经MLP成64维，与64维点描述子计算归一化点积×20，再加共享point/query组合评分MLP。训练每batch随机从当前训练观测的canonical标签中采24query，因此不是26工程点分类器。loss为同一query与候选canonical距离构造的soft交叉熵（sigma0.01），允许重复/近邻参考采样。

均batch8、256候选点、1200steps、Adam0.001、seed0/1/2，每200步只开发选checkpoint。数据/法向/旋转增强沿主合同；固定参数不根据080–099结果调优。考试沿同一180case与26工程query（9×3最近样本去重后实际26个）。

主指标沿同一可见query身份距离/当前扫描位置距离/P95、query覆盖；不可见query不算定位准确率，不补出伪答案。共享候选point索引，argmax获取当前候选，从当前扫描顶点保存face/bary=one-hot角点（不是SAM/MHR预测面）。

本阶段是前馈查询架构原型，不等于顶会贡献或机器人验收。尚无MHR↔FAUST对应、俯卧独立真值或临床标签。完成后再决定有无值得放大规模的query方法信号；保留弱于baseline的结果。
